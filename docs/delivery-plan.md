# 观澜：阶段实施计划

状态：已进入完整第一版实施。NestJS 五个业务模块与 MySQL 贯通验证已落地，安卓客户端正在构建与交互联调。更新：2026-09-12。

本文件保留分阶段设计；当前运行方式与验证证据以[交付记录](../README.md)和[部署说明](../../tuanzi-server-base/docs/plans/2026-09-12-guanlan-runbook.md)为准。

不按未验证的工期承诺日期。原型和接口验证完成后，再估算各阶段工作量。阶段按用户可检查的结果划分。

| 阶段 | 工作与交付物 | 验收条件 | 前置依赖 |
| --- | --- | --- | --- |
| 0 需求与方案 | 范围、技术比较、数据与预警限制、待定项 | 用户能明确哪些是已确认需求、建议和未知；确认方向后进入原型 | 当前讨论 |
| 1 交互原型 | 独立可点击手机原型；演示数据明确标注 | 能走完“条件筛选→候选比较→AI依据→加入观察→预警→复盘”，并看到空、加载、失败状态 | 主流程确认 |
| 2 技术验证 | 安卓工具链、图表触控试验、行情接口样本、指标口径说明、AI结构输出样本、推送路径验证 | 指标样本一致性可解释；数据覆盖与限制有实测记录；图表真机可操作；后台预警若必需则有可行通道 | 技术方向、测试设备；部分服务需账号与预算 |
| 3 第一条可用流程 | 自选池日线指标筛选、候选AI比较、观察留档 | 同一筛选快照可重复计算；报告可追溯；AI或行情失败不丢数据 | 数据、指标与AI验证 |
| 4 基础看盘完善 | 分时、K线交互、内置指标参数、全市场批量筛选 | 周期与复权可辨识；全市场覆盖和进度可见；限流失败可恢复 | 数据覆盖和图表验证 |
| 5 预警与复盘 | 策略保存、预警规则/事件/通知、大盘与个股复盘、AI 对话、备份恢复 | 持续命中去重；通知失败可查；复盘对象/日期和对话上下文正确；恢复后记录完整 | 部署与通知模式确认 |
| 6 个人试用交付 | 签名APK、服务部署说明、恢复步骤、已知限制 | 真机走通主流程，断网/重启/后台行为有证据；所有第一版需求逐项核对 | 前述阶段完成 |

## 原型页面清单

| 页面 | 核心交互 | 特别要评审 |
| --- | --- | --- |
| 看盘／自选 | 搜索、分组、打开个股 | 信息密度与单手操作 |
| 个股详情 | 分时与K线、指标参数、添加观察和预警 | 参数、周期、复权和时间是否清楚 |
| 筛选编辑 | 范围、指标、条件、参数、保存 | 不写公式也能配置；多个条件关系明确 |
| 候选结果 | 命中原因、排序、勾选、发起AI比较 | AI前仍可独立理解入选原因 |
| AI 比较与报告 | 多股比较、依据、信息缺口、加入观察 | 是否真的帮助缩小范围；避免单一神秘分数 |
| 观察与预警 | 原始理由、规则开关、触发历史 | 运行与送达状态区分，关闭APP后的行为清楚 |
| 大盘与个股复盘 | 选择对象和日期、回顾信号、保存笔记、追问 AI | 信息缺口明确、上下文可追溯 |
| AI 复盘聊天 | 大盘／个股／筛选上下文、新对话、连续追问、历史查看与确认删除 | 上下文和数据日期清楚，回复引用可检查 |
| 设置 | 服务连接、通知、数据与备份 | 产品必要配置可懂；技术细节留在部署文档 |

## 阶段边界

- 正式客户端在 android-native，正式后端在 tuanzi-server-base；早期 React/Node 试写代码不作为当前入口。
- 原型是交互验证材料，不接真实资金或假装实时行情；浏览器原型不等于正式安卓APP。
- 先评审具体方案与原型，再按确认范围进入正式实施。用户已有授权可覆盖后续步骤时不重复索要许可。
- 第一条可用流程仅为中间里程碑，不能把它称为包含分时、预警和复盘的完整第一版。
- 不包含自定义指标引擎、公式兼容、自动下单、完整回测、券商账号接入、交易复盘与盈亏核算。

## 主要风险及收敛方式

| 风险 | 影响 | 收敛方式 |
| --- | --- | --- |
| 数据接口与权限不满足 | 分时、全市场筛选受限 | 在正式开发前实测样本与额度，必要时更换数据源 |
| 指标口径不同 | 与现有软件结果不一致 | 固定参数与复权样本对照，公开差异，不只比较指标名称 |
| AI 缺乏有效证据 | 报告空泛或误导 | 固定输入与来源校验，缺信息明确说明，保留未选候选用于跟踪 |
| 安卓后台送达不可靠 | 错过提醒 | 服务端监控与设备推送分别验证；不承诺必达 |
| 全市场与批量AI调用量大 | 时间与成本增加 | 行情缓存、任务进度、用户选择分析范围、预算限制 |
| 个人记录丢失 | 复盘不可恢复 | 本地持久化、同步版本控制、备份恢复验收 |
